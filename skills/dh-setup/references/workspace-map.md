# Workspace map (`WORKSPACE.md`)

`{workspace_root}/WORKSPACE.md` is the harness's source of truth for a
monorepo: which packages exist, their stacks and commands, where docs live, and
what scope the code graph, worktrees and releases use. `dh-setup` is its only
generator and it lives at the workspace root (`WORKSPACE.md`; `docs/WORKSPACE.md`
is accepted as a fallback). Other skills read it (root first, then `docs/`);
when it is absent **and no workspace marker was detected**, they fall back to
the single project root. A detected workspace with a declined or missing map
stops for explicit confirmation instead of degrading silently.

Roots: the **workspace root** owns `docs/plans`, `AGENTS.md`, the `dh` MCP entry
and the root `WORKTREE_LIFECYCLE.md`; a **package root** owns its stack,
commands, optional `CODE_RULES.md`, docs and worktree lifecycle. Plans stay at
the workspace root only — a package-local `docs/plans` is never created.

## Detection markers

Require a marker **plus user confirmation**: a nested `package.json` alone does
not make a workspace.

| Marker | Layout | Proves |
|---|---|---|
| `pnpm-workspace.yaml` | pnpm workspace | `packages:` list (a settings-only file with no `packages:` key is not a workspace) |
| `package.json#workspaces` | npm / yarn workspaces | Array or `{ packages: [...] }` |
| `turbo.json` | Turborepo | Task pipeline over the package manager's workspace list |
| `nx.json` | Nx | `workspace.json` / `project.json` projects; Nx may run without package manifests |
| `lerna.json` | Lerna | `packages` globs (legacy npm/yarn workspaces) |
| Cargo `[workspace]` in `Cargo.toml` | Rust workspace | `members` / `exclude` crate list |
| `go.work` | Go workspace | `use` module directories |
| `settings.gradle` / `settings.gradle.kts` | Gradle multi-project | `include(...)` subprojects |
| `*.sln` | .NET solution | Referenced `*.csproj` projects |
| `.gitmodules` | Git submodules | `path` entries are package roots; each is its own repository |

Procedure:

1. Probe upward from the cwd to the filesystem root (and one level below),
   ignoring `node_modules`, `dist`, `.git`, vendor and build directories.
2. Record every marker found with its evidence (file + key + value). Two
   markers for the same layout are one workspace, not two.
3. Resolve package paths from the marker's own list; do not guess from
   directory names.
4. Treat `.gitmodules` entries as package roots too: `git rev-parse --show-toplevel`
   inside one returns the submodule, so never use git toplevel alone to find the
   workspace root.
5. If a marker is found above the cwd, stop: the session did not start at the
   workspace root. Require a restart there before any plan/doc write.
6. Confirm the detected layout with the user before writing anything. No marker
   and no confirmation → standalone (see below). A marker found but the map
   declined → stop for an explicit standalone override; do not degrade silently.

## Interview

Ask per package group and record the answers in the map:

1. **Root:** is `{workspace_root}` the repository that owns `docs/plans`? Any
   package that must stay outside it?
2. **Packages:** which detected paths are real packages, and which are vendored,
   generated, archived or fixtures?
3. **Stacks:** primary language/runtime per package; polyglot packages list each
   stack.
4. **Test command:** the exact per-package test command (or `none` with the
   reason).
5. **Build command:** the exact per-package build/typecheck command (or `none`).
6. **Aggregate:** the workspace-level command (`pnpm -r`, `nx run-many`,
   `turbo run`, `cargo test --workspace`, `go test ./...`, `gradle build`,
   `dotnet test`).
7. **Docs roots:** does each package keep `docs/` of its own, or does everything
   live under the workspace `docs/`? Which frontmatter `package` value labels
   package docs?
8. **Code graph:** one workspace index or one index per package? Which paths are
   excluded?
9. **Worktrees:** which packages carry their own `WORKTREE_LIFECYCLE.md`? Are
   submodule branches aligned with the workspace branch?
10. **Version policy:** `fixed` (one tag for the workspace) or `independent`
    (per-package tags)? Default `fixed`; require an explicit answer for
    independent.
11. **Rules:** root `CODE_RULES.md` defaults plus per-package overrides, or
    root-only?
12. **Consent:** may the map be written at `{workspace_root}/WORKSPACE.md`
    (otherwise `docs/WORKSPACE.md`)? Is `DH_WORKSPACE_ROOT` written into the
    project `opencode.jsonc`?

## Template

Write only after consent. Never overwrite an existing map without showing the
diff and getting approval.

```markdown
# Workspace Map

> Generated by dh-setup on <YYYY-MM-DD>; reviewed with the user. Update when a
> package is added/removed or a command changes.

## Workspace root

- Path: `<absolute workspace root>`
- Layout: pnpm | npm/yarn | Nx | Turbo | Lerna | Cargo | Go | Gradle | .NET | submodules | mixed
- Markers: `<marker files and keys>`
- Plan root: `docs/plans` (workspace root only; package-local plan dirs unsupported)

## Packages

| Package | Path | Stack | Test | Build | Docs root | Rules | Notes |
|---|---|---|---|---|---|---|---|
| web | `apps/web` | TypeScript/React | `pnpm --filter web test` | `pnpm --filter web build` | `apps/web/docs` | `apps/web/CODE_RULES.md` | |
| api | `services/api` | Python | `uv run pytest` | `uv run mypy .` | workspace `docs/` | root | |

## Aggregate commands

- Test: `<workspace test command>`
- Build: `<workspace build command>`
- Affected only: `<affected command>`

## Docs roots

- Workspace docs: `docs/` (vault = workspace root unless `OBSIDIAN_VAULT` is set)
- Package docs: `<package>/docs` with frontmatter `package: <name>`
- Evolution and observation notes: workspace `docs/evolution/`

## Code-graph scope

- Index: workspace | per package
- Included paths: `<paths>`
- Excluded paths: `<paths>`

## Worktree scope

- Workspace lifecycle: `WORKTREE_LIFECYCLE.md`
- Package lifecycles: `<package>/WORKTREE_LIFECYCLE.md` or `none`
- Submodule branch policy: aligned with the workspace branch | independent

## Version policy

- Policy: fixed | independent
- Tag format: `vX.Y.Z` | `<package>@X.Y.Z`
- Changelog: workspace `CHANGELOG.md` | per package
```

## `DH_WORKSPACE_ROOT` wiring

The `dh` MCP server resolves its root as `DH_WORKSPACE_ROOT` when non-blank,
else the process cwd, and anchors plans at `<root>/docs/plans`. Set the override
to the **absolute** workspace root in the `dh` entry's `environment` block
(relative values depend on the cwd and are rejected by the anchor check):

```jsonc
{
  "mcp": {
    "servers": {
      "dh": {
        "type": "local",
        "command": ["npx", "-y", "--package=github:andrescevp/development-harness", "dev-harness-mcp"],
        "protocol": "2026-07-28",
        "timeout": { "startup": 300000 },
        "environment": { "DH_WORKSPACE_ROOT": "/absolute/workspace/root" }
      }
    }
  }
}
```

- Unset is valid when every session starts at the workspace root.
- The root resolves per connection: restart opencode after editing the entry and
  re-verify.
- Preserve unrelated keys (`disabled`, `codemode`, other servers) and comments;
  the canonical-field comparison in `dh-setup` Step 3 does not treat
  `environment` as a conflict.
- The vault is independent: `OBSIDIAN_VAULT` moves docs only, never
  `docs/plans`.

## Anchor verification

Run at the start of Step 3 and repeat after wiring; report each result:

1. `pwd -P` equals the workspace root that holds the map/markers and
   `docs/plans` (resolve symlinks — the MCP compares realpaths).
2. `git rev-parse --show-toplevel` equals the workspace root; inside a submodule
   also check `git rev-parse --show-superproject-working-tree`.
3. `DH_WORKSPACE_ROOT` is unset or an absolute path equal to the workspace root
   after realpath normalization.
4. `dh_plan_read` on an existing plan returns a path under
   `<workspace_root>/docs/plans`.
5. The skill-side `./docs/plans` resolves to that same directory (it does when
   the session base is the workspace root).
6. No `<package>/docs/plans` exists; if one does, report it as foreign and leave
   it untouched.

Any mismatch → stop before the first write, name both roots and both plan
directories, and tell the user to restart opencode at the workspace root with
`DH_WORKSPACE_ROOT` unset or equal to it. Reading is the only operation a user
may explicitly authorize under mismatch; never create the missing plan
directory to "fix" the split.

## Standalone fallback

No markers and no map: keep today's behavior exactly. `cwd = workspace root =
package root = plan root = vault root`; `./docs/plans` keeps its meaning;
`DH_WORKSPACE_ROOT` may stay unset (if set it must equal the cwd); one
toolchain, one full diff. A standalone repository is never required to add a
map, a marker or an override.

## Validation checklist

- [ ] Every marker found is recorded with its evidence, and the layout was
      confirmed by the user (no workspace inferred from one nested
      `package.json`).
- [ ] Every package row has a path, stack, test command and build command (or an
      explicit `none`).
- [ ] Aggregate commands and the affected-only command are filled or marked
      `none`.
- [ ] Docs roots, code-graph scope, worktree scope and version policy are
      present; version policy is explicit.
- [ ] `pwd -P` equals the workspace root; `DH_WORKSPACE_ROOT` is unset or an
      absolute path equal to it.
- [ ] The `dh` plan dir and the skill `./docs/plans` agree; no package-local
      `docs/plans` exists.
- [ ] The map was written only with consent; an existing map was reviewed, not
      overwritten.
- [ ] Standalone projects and unrelated config keys are unchanged.
- [ ] The setup report lists the detected layout, the packages and the anchor
      result.
